# ДЗ №1, семестр 2, вариант 9

Консольная программа на C++11. Часть 1: потоки и последовательные контейнеры STL.
Часть 2: задача №29, бинарная база сотрудников `Person` и индекс на основе `std::map`.

## Сборка и запуск

Нужен компилятор с поддержкой C++11. Из папки `dz1_sem2`:

```sh
make
./build/dz1_sem2
```

Без `make`:

```sh
g++ -std=c++11 -Wall -Wextra -Wpedantic main.cpp sequence.cpp personnel.cpp -o dz1_sem2
./dz1_sem2
```

Для Windows при прямой сборке имя программы можно задать как `dz1_sem2.exe`.
Исходные файлы и сообщения — UTF-8; терминал должен поддерживать эту кодировку.
Qt и сторонние библиотеки не нужны. Относительные имена файлов считаются от текущей
рабочей папки программы. Пути с пробелами вводятся целой строкой, без кавычек.

Создание исходных файлов, сохранение результатов, выборок и ведомостей требует
**нового имени**: существующие читаемые файлы программа не перезаписывает.
Удаление и замена записи в открытой базе выполняются отдельными командами меню.

## Часть 1

В меню доступны два способа генерации 100 целых чисел из `[-50, 50]`:

1. Запись через файловый поток в цикле.
2. `generate` для заполнения вспомогательного контейнера и `copy` с `ostream_iterator`.

Загрузка и сохранение имеют по две версии: обычные потоки и алгоритм `copy` с
потоковыми итераторами. Загрузка алгоритмом использует `back_inserter`.

Для обработки в памяти выбираются `vector`, `deque` или `list` и один из методов:

1. Шаблонная функция с аргументом-контейнером.
2. Функция с входными и выходным итераторами.
3. `for_each`, операция передаётся лямбда-функцией.

Четвёртый метод — непосредственный `transform` между потоковыми итераторами файла.
Он не зависит от контейнера и потому не запрашивает выбор контейнера и отдельного
способа загрузки/сохранения. Предварительный проход проверяет весь файл и находит
первое отрицательное число; следующий проход одновременно читает, преобразует и
записывает числа. Он также накапливает статистику, не сохраняя последовательность.

Правило варианта: **каждое чётное число умножается на первое отрицательное число
исходного набора**. Чётность относится к значению, а не позиции. Ноль тоже чётный.
Множитель сохраняется до обработки и не изменяется, даже если соответствующий
элемент сам преобразуется.

После обработки дописываются:

- сумма модулей преобразованных значений `S = sum(abs(y))`;
- среднее модулей `A = S / N`, где `N` — число значений до добавления итогов.

Итоги одинаково добавляются во всех четырёх вариантах. Исходные контейнеры содержат
`int`, результирующие контейнеры того же вида — `double`, чтобы среднее не усекалось.
Конкретные типы выбираются в `main.cpp`; в шаблонах используются `value_type`,
`size_type`, `iterator_traits` и другие зависимые типы.

Пример из `examples/input.txt`:

```text
Вход:              2 5 -3 -4 0 7
Множитель:        -3
Преобразование:   -6 5 -3 12 0 7
Сумма модулей:   33
Среднее модулей:   5.5
```

Полный ожидаемый файл: `examples/expected.txt`. Для примера в меню первой части
выберите пункт 3, вход `examples/input.txt`, метод 1–4 и новое имя, например
`result1.txt`. Методы 1–3 дополнительно запросят контейнер, способ загрузки и записи.

Генераторы создают ровно 100 чисел; функции загрузки допускают и меньшие учебные
наборы для проверки. Каждый входной токен должен быть целым числом в `[-50, 50]`.
Дроби, посторонние символы и переполнение отвергаются, включая последний токен
без перевода строки. Пустой файл и отсутствие отрицательного множителя приводят
к сообщению об ошибке. Нечётные числа не изменяются; исходный файл сохраняется.

## Часть 2

Пункты меню позволяют создать и открыть базу, показать записи, добавить, заменить
или удалить сотрудника, сохранить выборку и сформировать текстовую ведомость.

`Person` содержит табельный номер, отдел, ФИО, пол, оклад, дату приёма, процент
надбавки, подоходный налог, отработанные и рабочие дни, начисленную и удержанную
суммы. Пол добавлен потому, что он требуется критерием поиска, хотя пропущен
в перечне полей условия. Используются обозначения `M` и `F`.

Все поля вводятся пользователем. Формула начисления и удержания в задании
отсутствует; программа не вводит её самостоятельно. Подоходный налог хранится
как денежная сумма. «Начислено» и «Удержано» также вводятся готовыми значениями;
«К выплате» вычисляется как их разность. Эти поля не пересчитываются из оклада.

Табельный номер уникален и положителен, номер отдела положителен. Дата проверяется
по календарю, включая високосные годы. ФИО — непустая строка до 127 байт UTF-8.
Денежные поля и процент конечны и неотрицательны; рабочих дней от 1 до 31,
отработанных — от 0 до количества рабочих. Удержано не превышает начисленное.

В бинарный файл записывается и читается **целый объект** `Person`, одним
`write`/`read` на запись. ФИО хранится в фиксированном символьном массиве, дата —
в простой структуре; указателей, `std::string` и контейнеров внутри записи нет.
Бинарный формат предназначен для совместимых сборок этой программы; перенос между
компиляторами и архитектурами с иной раскладкой структуры не предусмотрен.

Индекс `map<int, streampos>` сопоставляет табельный номер позиции записи в файле.
Он строится при открытии базы, обновляется при добавлении и перестраивается после
удаления/замены. Поиск по отделу, полу и точной дате приёма возвращает все совпадения
и записывает их в **отдельный новый бинарный файл**. Выборку можно открыть как базу.
При отсутствии совпадений создаётся корректный пустой файл.

Удаление и замена переписывают базу в новый файл с суффиксом `.tmp`. После проверки
нового файла исходник временно переименовывается в `.bak`, затем новый файл получает
имя базы. При ошибке переименования исходное имя восстанавливается. После успеха
резервный файл удаляется; существующие `.tmp` и `.bak` программа не затирает.
Ведомость — текст с разделителями-табуляциями,
содержит все поля, сумму к выплате и общие итоги: количество сотрудников, начислено,
удержано, к выплате. Дублирующиеся номера и неполная последняя бинарная запись
считаются ошибками.

## Проверки

```sh
make test
```

Тесты запускаются в новом подкаталоге `build`, пользовательские базы не используются.
Проверяются три контейнера, все четыре метода обработки, два метода загрузки и
сохранения, дробное среднее, фиксированный множитель, некорректный ввод, работа
сотрудников и перестроение индекса. Папка `build` исключена из Git.

При прямой сборке тестов:

```sh
g++ -std=c++11 -Wall -Wextra -Wpedantic tests.cpp sequence.cpp personnel.cpp -o tests
mkdir test-data
./tests test-data
```

Каталог для каждого повторного запуска тестов должен быть новым и пустым.
